以下既有产品文案作为本轮语气参照：

| 场景 | 现有文案 | 保留的写法 |
| --- | --- | --- |
| 公开首页主张 | “每天一份，只为你而编的私人日报。” | 短句，先说用户得到的结果 |

## Sepia defect list（修改前）

1. **公开首页**：正文中的“把结果整理成稳定、可追溯”偏抽象；“交付一次 Token”不是用户会说的动作；三步说明重复出现 Agent，第二步没有明确“只显示一次”的后果。
2. **登录**：`Sign in or create account` 是通用模板标签；“不需要先判断自己是在登录还是注册”绕着产品行为说；网络失败提示使用“网络请求没有完成”，更像内部日志。
3. **首次使用与昵称**：设置话术中的“用起来”没有说明下一步；“会主动向你索取”省略了 Token；“等 Agent 向你索取”和“创建后继续留在 Agent 对话里”动作边界不够直接；昵称页按钮“保存并连接 Agent”把尚未发生的连接说成了当前动作。
4. **Home 与系统示例**：`系统内置 · 不代表今日` 不如“系统示例”直观；系统示例仍使用“今日总览”和“等待 / 到达”类表达，容易把示例或最新一期误读为今天的运行状态；“连接 Agent 后”也把连接与首份正式内容混在一起。
5. **日报阅读**：“更新一期”可能被理解为刷新页面；历史期次使用“今日编辑”；空状态用“日报还没有到达”和“替你回退”描述实现行为；来源对话框的“来源清单”与页面“全部来源”重复但不统一。
6. **Todo**：页面说明“继续告诉你的 Agent”带有不必要的上下文假设；空分组“这一组暂时没有事项”偏书面；日期与完成状态可以更直接；保持只读、正式 State 和五个分组事实不变。
7. **设置与确认**：主题预览写成“固定内容预览”并带“今日”示例；主题说明对 Home 使用场景不准确；“配置 / 打开”缺少对象；“安全保存”“清晰的设置话术”“物理删除”和“正式内容”属于机器腔或技术表达；部分按钮和状态没有说清动作对象。
8. **统一错误与反馈**：表单错误大多可用，但“没有找到可轮换的”“暂时无法保存”等句式需要保持用户可执行的下一步；不改稳定机器错误码、HTTP 状态、安全检查和权限后果。
9. **公开 Agent Markdown**：入口 front matter 声称“continuously updated”，超出 DailyNews 能确认的自动更新事实；入口介绍、能力检查和完成条件重复说明“读取 / 确认 / 完成”，可压缩为直接步骤。Content、Todo、Theme 文档中的路径、字段、错误码、幂等和安全边界是机器合同，只做外围句子的清理。

## 不在本轮修改

- 不改主 Slogan、用户生成的昵称 / 日报名称 / 内容正文、来源标题、API 路径、字段、状态码、权限、安全提示或 Token 显示边界。
- 不把 Agent 在线、调度、自动更新或“连接成功”写成服务端无法确认的产品状态。
- 不改路由、业务逻辑、数据模型、主题、布局、构建或部署。
